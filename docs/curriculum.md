# Go Gin 后端实战课程

本课程面向“会其他语言，Go 刚入门”的学习者，通过一个本地学习任务管理后端，提高 Go 编码、调试和解释常见面试知识的能力。课程包含 16 节主线课和 4 个专题，每一课都通过实际功能或小实验学习。

课程安排是后续工作的依据。课程课次使用 L01 到 L16，专题使用 T01 到 T04；实际练习使用独立任务编号 001、002 等。一课可以拆成多个任务，课程表中的后续内容属于规划，逐课布置时才创建任务发布记录和提交。

## 课程目标与项目范围

最终项目提供注册登录、任务增删改查、筛选分页、完成任务并记录日志，以及同步批量导入任务的接口。通过接口工具操作，保持业务规模小。

主线按 Go、Gin、MySQL 的顺序引入工具，数据先保存在内存中，再替换成数据库。先使用 `database/sql` 理解查询、连接池和事务。Redis 在 T04 中加入；ORM 的对比可以在理解 SQL 后另做选学练习。

最终业务表控制在三张：

| 表 | 用途 | 主要字段 |
| --- | --- | --- |
| users | 用户和登录 | id、用户名、密码哈希、创建时间 |
| tasks | 学习任务 | id、user_id、title、done、创建和更新时间 |
| task_logs | 任务完成记录 | id、task_id、操作类型、创建时间 |

任务起步保留当前的 `ID`、`Title`、`Done` 字段，后续按需要补充用户和时间字段。筛选任务时使用完成状态，避免为了练习添加大量业务状态。

计划中的接口如下，实际接口契约在对应任务中确定：

| 接口 | 用途 | 对应课程 |
| --- | --- | --- |
| GET /health | 服务健康检查 | L04 |
| POST /tasks | 创建任务 | L05 |
| GET /tasks | 列表、状态筛选与分页 | L05、L11 |
| GET /tasks/:id | 查询任务详情 | L05 |
| PATCH /tasks/:id | 修改任务字段 | L05、L07 |
| DELETE /tasks/:id | 删除任务 | L05 |
| POST /tasks/:id/complete | 完成任务并写入日志 | L12 |
| POST /auth/register | 注册用户 | L13 |
| POST /auth/login | 登录 | L13 |
| POST /tasks/import | 同步批量导入任务 | L14 |

## 学习节奏

主线建议投入约 30 到 40 小时。按每周约 5 小时安排，预计 6 到 8 周；4 个专题可再投入约 8 到 12 小时。时间为规划估计，环境配置、排错和复习可能需要额外时间，以理解和验收结果决定推进速度。

每次约 60 分钟的练习可以这样分配：

1. 10 分钟理解需求和知识点。
2. 35 分钟自己写代码、运行和调试。
3. 10 分钟制造并处理一个边界情况。
4. 5 分钟用自己的话解释两个面试问题。

每个任务保留代码、验证结果和问题解释。先尝试独立完成，卡住时获取提示或局部示例，再自己重写。任务完成后按 [AGENTS.md](../AGENTS.md) 提交并推送，记录题目、实际问题、处理方式和验证结果。

可以使用下面的八周安排。有些周的预计投入接近 6 小时，超出可用时间时顺延；每周保留复习和排错时间，不为赶进度跳过验收。

| 周次 | 建议内容 |
| --- | --- |
| 第 1 周 | L01 到 L03，完成基础语法、集合和函数练习 |
| 第 2 周 | L04、L05，完成 HTTP 入门和内存 CRUD |
| 第 3 周 | L06、L07，处理并发和非法输入 |
| 第 4 周 | L08、L09，理解中间件并拆分职责 |
| 第 5 周 | L10、L11，接入数据库并观察索引 |
| 第 6 周 | L12、L13，验证事务、幂等和用户权限 |
| 第 7 周 | L14、L15，完成取消、测试和性能观察 |
| 第 8 周 | L16，整理运行说明，做项目演示和口述复盘 |

专题可以按前置知识穿插，也可以在主线之后再完成。

## 第一阶段 Go 基础

### L01 环境与第一条任务

**目标：** 能创建 Go 模块、定义结构体并运行程序。

**练习：** 配置工具，创建模块；定义包含 ID、Title、Done 的 Task，创建并打印任务，然后修改完成状态并再次打印。

**知识：** package、module、`go.mod`、标准库导入、程序入口、字段类型、`:=`、`fmt.Printf`、编译和运行。依赖引入后再观察 `go.sum` 的作用。

**验收：** 程序正常退出，打印未完成和已完成两条任务；能解释入口函数、变量声明和输出格式。

**口述问题：** package 与 module 有什么区别？重新给结构体赋值与修改一个字段有什么区别？

### L02 零值与数据集合

**目标：** 能选择并使用 slice 和 map 保存多个任务，理解当前结构体的复制行为。

**练习：** 先完成零值和结构体复制实验；再用切片保存三条任务，追加、遍历和筛选；用 map 按 ID 查询任务；观察切片赋值、`append` 和底层数组共享的情况。

**知识：** 零值、数组和切片、len/cap、append、make/new、map 查询的第二个返回值、值复制与共享数据。底层实现细节在 T01 补充。

**验收：** 能列出和筛选任务，正确区分“查不到”和有效零值；能用实际输出解释结构体复制和切片共享的差别。

**口述问题：** len 与 cap 分别表示什么？为什么复制切片后修改元素仍可能影响原切片？

### L03 函数与错误处理

**目标：** 把任务操作写成可独立调用的普通 Go 函数。

**练习：** 实现创建、查找和修改任务的函数；为空标题、不存在的 ID 返回错误；比较传入 Task 和传入 `*Task` 的行为；通过一个资源清理小实验观察 defer。

**知识：** 参数和返回值、多返回值、指针、值传递、方法、值接收者和指针接收者、error、defer。错误包装及 `errors.Is/As` 在 L07 继续练习。

**验收：** 正常输入得到正确结果，非法输入返回可识别的错误；通过实验解释哪些操作改变了调用者的数据。

**口述问题：** Go 函数参数怎样传递？defer 的执行顺序和参数求值时机怎样验证？

### L04 HTTP 与第一个 Gin 接口

**目标：** 理解一次请求怎样进入 Go 程序并生成响应。

**练习：** 先用 `net/http` 实现 `/health`，再用 Gin 实现同一接口；通过接口工具观察方法、路径、请求头、状态码和 JSON 响应。

**知识：** HTTP 请求和响应、常见状态码、JSON、Handler、Gin 与 `net/http` 的关系。结合本地请求解释 TCP 连接、HTTP 请求和 Keep Alive 的关系。

**验收：** 正常请求返回约定 JSON；错误路径和不匹配的方法有可解释的响应；能说明响应状态码与响应体各自表达什么。

**口述问题：** Gin 帮你处理了哪些 HTTP 开发工作？HTTP 状态码和业务错误码有什么区别？

**阶段验收：** 能写普通 Go 函数、处理集合和错误，并启动一个能响应请求的服务。

## 第二阶段 Gin 内存 API

### L05 内存版任务 CRUD

**目标：** 把任务操作暴露成可以实际调用的接口。

**练习：** 完成创建、列表、详情、修改和删除任务；使用路径参数和查询参数；约定 ID、响应格式和不存在的任务如何处理。

**知识：** Gin 路由、HTTP 方法、JSON 序列化、路径与查询参数、幂等性。并发正确性在 L06 专门验证。

**验收：** 从创建到修改、查询和删除完整调用一遍；缺失 ID 和重复删除等边界情况符合约定。

**口述问题：** PATCH 与 PUT 怎样选择？幂等是否要求每次请求返回完全相同的内容？

### L06 并发安全

**目标：** 发现并修复共享内存访问中的竞态。

**练习：** 并发调用内存仓库；在受控的小实验中复现不安全访问，再使用 Mutex 或 RWMutex 保护共享数据；检查 ID 生成和返回值是否也存在共享问题。

**知识：** goroutine、共享状态、临界区、Mutex、RWMutex、竞态检测；区分数据竞态、业务竞争和死锁。

**环境准备：** 本机为 Windows，进入本课时先检查竞态检测的 cgo 和 C 编译器条件，再准备所需工具；不把环境限制误判为代码问题。具体要求见 [Go 竞态检测环境说明](https://go.dev/doc/articles/race_detector#requirements)。

**验收：** 先记录失败实验，再使用 `go test -race` 检查包含并发场景的验证代码；检查结果和业务数量都符合预期，不把“没有报告竞态”当作所有场景都正确的证明。

**口述问题：** 为什么普通 map 的并发读写需要协调？锁放在仓库和 handler 中各有什么影响？

### L07 参数校验与错误响应

**目标：** 正确处理缺失、非法和部分更新的输入。

**练习：** 校验标题、ID 和分页参数；对比字段未提供与显式传入 `done: false`；统一错误响应，并把业务错误映射到 HTTP 状态码。

**知识：** struct tag、参数绑定和校验、请求 DTO、`BindJSON` 与 `ShouldBindJSON`、错误包装、`errors.Is/As`、可选字段。

**验收：** 非法 JSON、空标题、非法 ID 和显式布尔零值都有正确行为；不会只更新一个字段却把其他字段意外清零。

**口述问题：** 如何区分字段没传和传了零值？为什么需要保留错误原因并在边界层转换响应？

### L08 中间件

**目标：** 用中间件处理横跨多个接口的行为。

**练习：** 增加请求 ID、访问日志和简单的请求拦截实验；打印嵌套中间件的执行顺序；使用 Recovery 观察一个受控 handler panic 的响应。

**知识：** 中间件注册范围、`Next`、`Abort`、panic/recover、Gin Recovery、`gin.Context` 与标准 `context.Context` 的职责。实际登录鉴权在 L13 实现。

**验收：** 日志包含请求 ID 和处理耗时；拦截后目标 handler 不执行；能按实验结果解释中间件顺序和 panic 处理边界。

**口述问题：** `Next` 与 `Abort` 分别控制什么？Recovery 能处理哪些位置发生的 panic？

**阶段验收：** 内存 API 功能完整，非法输入有清楚的响应，并发访问经过验证，中间件行为能通过实际日志解释。

## 第三阶段 数据库与后端核心问题

### L09 分层与接口

**目标：** 在换存储方式时保留已有业务行为。

**练习：** 逐步把入口、HTTP 处理、业务规则和数据访问分开；为真实需要替换的仓库定义小接口；通过构造函数传入依赖；实验接口中包含带类型的 nil。

**知识：** handler、service、repository、隐式接口实现、方法集、依赖注入、接口零值。目录按实际职责逐步拆分。

**验收：** 拆分前后接口行为一致；service 能在不启动 HTTP 服务时使用内存仓库；能解释每个接口为何存在。

**口述问题：** 接口通常应该定义在使用方还是实现方？接口变量为什么可能包含 nil 指针却不等于 nil？

### L10 MySQL 持久化

**目标：** 使用 `database/sql` 替换内存存储，理解资源和连接管理。

**练习：** 建立三张表并保存建表脚本；用参数化 SQL 实现任务操作；处理无结果、查询迭代错误和资源释放；配置并观察连接池。鉴权前使用明确标注的本地测试用户数据。

**知识：** 数据库驱动、`sql.DB`、连接池、Query/QueryRow/Exec、Scan、`sql.ErrNoRows`、参数化查询、`rows.Close` 和 `rows.Err`、请求 context。

**验收：** 重启服务后任务仍可查询；缺失记录正确映射为业务错误；配置错误和数据库连接失败可以定位；可重复准备本地数据库环境。

**口述问题：** `sql.DB` 表示一条连接还是数据库访问入口？为什么必须处理查询迭代错误和资源关闭？

### L11 分页与索引

**目标：** 让查询结果稳定，并通过实际执行计划理解索引。

**练习：** 按 user_id 和 done 筛选，约定稳定排序和分页上限；准备足量测试数据；对比添加联合索引前后的 EXPLAIN；观察 OFFSET 分页和游标分页的取舍。

**知识：** 联合索引、最左前缀、排序、覆盖索引、执行计划、分页边界。测试规模与结果一起记录，不把小数据集的耗时推广为通用结论。

**验收：** 给定排序规则后分页行为稳定；非法分页参数被正确处理；能引用实际执行计划解释索引是否被使用。

**口述问题：** 为什么索引字段的顺序会影响查询？深分页为什么可能越来越慢？

### L12 事务与重复请求

**目标：** 保证任务完成和日志写入作为一个整体成功或失败。

**练习：** 实现完成任务接口，将状态更新和日志写入放在同一事务中；故意让日志写入失败；明确重复完成的响应规则，并通过条件更新或约束避免重复完成记录；加入并发重复请求验证。

**知识：** ACID、事务开始和提交、回滚、隔离级别、锁、MVCC 的基本作用、幂等性。所有事务内查询通过同一个事务对象执行。

**验收：** 正常请求同时更新状态和写入日志；日志写入失败时状态回滚；并发重复请求的最终状态和日志数量符合约定。

**口述问题：** 为什么两个成功的独立 SQL 操作不等于一次原子业务操作？事务和幂等性分别解决什么问题？

**阶段验收：** 数据持久化、查询行为和事务失败场景均有实际验证，能用执行计划和结果解释数据库设计。

## 第四阶段 可靠的小服务

### L13 登录与用户权限

**目标：** 区分认证与授权，并正确限制任务归属。

**练习：** 实现注册、密码哈希校验和 JWT 登录；读取本地配置中的签名密钥；校验签名、预期算法和过期时间；所有任务访问按当前用户归属检查。

**知识：** 密码哈希与加密、JWT、认证与授权、401/403、水平越权、配置与凭据管理。使用成熟库处理密码哈希和令牌验证。

**验收：** 两个用户分别创建任务；错误密码、过期或被篡改的令牌被拒绝；跨用户查看、修改和删除被拒绝；日志和响应不暴露密码或令牌。

**口述问题：** 解析出 JWT 内容为什么不代表验证成功？用户已登录为什么仍需检查任务归属？

### L14 并发处理与取消

**目标：** 控制并发量，让请求结束时相关工作也能结束。

**练习：** 使用固定数量 worker 同步处理 CSV 批量导入，限制输入规模和排队容量；传递请求 context；实验超时、取消、错误汇总和通道关闭。主线中所有 worker 在响应返回前结束，持久化异步任务另行规划。

**知识：** channel、select、WaitGroup、context、背压、worker pool、goroutine 泄漏；HTTP 并发、worker 数量与数据库连接池的关系。

**验收：** 正常批量导入数量正确；达到容量限制时行为明确；取消或超时后 worker 能退出，未启动的工作停止进入队列；没有在后台继续使用 Gin 请求上下文。

**口述问题：** 谁应该负责关闭 channel？为什么限制 worker 数量仍需要考虑排队容量和数据库连接？

### L15 测试与性能定位

**目标：** 用自动化检查验证行为，用观测结果定位问题。

**练习：** 写表驱动的业务测试和 httptest 接口测试，覆盖非法输入、任务归属、重复请求和事务回滚；添加必要的并发场景；使用 benchmark 和 pprof 观察 CPU 或分配热点，测量一个优化是否有效。

**知识：** 表驱动测试、子测试、httptest、测试替身、集成测试、竞态检测、benchmark、pprof。数据库测试使用单独测试数据并说明准备方式。

**验收：** 已实现的关键行为有可重复检查；测试发现错误时能解释原因；性能比较记录数据规模、运行条件和结果，无明显收益也如实记录。

**口述问题：** 单元测试和集成测试各验证哪些风险？为什么一次耗时变化不足以证明性能优化有效？

### L16 配置与优雅退出

**目标：** 让服务启动失败可定位，退出时可收尾。

**练习：** 用环境变量管理端口、数据库和密钥配置，提供不含真实凭据的示例；配置 HTTP 超时；退出时停止接收新请求，取消或等待工作，最后关闭数据库等资源；整理启动和验证说明。

**知识：** 配置校验、HTTP 服务超时、请求生命周期、退出信号、Shutdown、context deadline、资源清理、连接管理。

**验收：** 缺失必要配置时给出明确错误；正常启动和健康检查可重复；本地退出实验中已有请求和 worker 按约定收尾；其他环境可以根据说明准备依赖并启动。

**口述问题：** 优雅退出的操作顺序为什么重要？HTTP 超时、业务超时和数据库查询超时怎样配合？

**阶段验收：** 能演示登录与归属检查、取消与退出、关键自动化测试，以及一次真实的性能观察。

## 主线结课验收

1. 根据仓库说明准备环境并启动服务，演示任务增删改查、筛选分页和重启后数据保留。
